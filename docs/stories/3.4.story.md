## Story

**Como** administrador da AISphere,
**quero** usar as chaves já geradas para integrar sistemas internos à plataforma,
**para** consultar dados e registrar interações, ações e eventos sem preenchimento manual duplicado.

## Acceptance Criteria

1. Todos os endpoints usam o prefixo versionado `/api/v1` e exigem `Authorization: Bearer <chave>` ativa.
2. A chave é comparada pelo hash armazenado, nunca registrada em claro, e seu `last_used_at` é atualizado após autenticação válida.
3. A API retorna JSON consistente para sucesso e erro, com códigos HTTP adequados e sem detalhes internos ou segredos.
4. `POST /api/v1/interactions` cria uma interação após validar referências, tipo, relevância, campos obrigatórios e datas.
5. `GET /api/v1/clients` consulta clientes ativos com paginação e filtro textual opcional.
6. `GET /api/v1/people` consulta pessoas com paginação e filtros opcionais por cliente ou texto.
7. `POST /api/v1/actions` cria uma ação e `PUT /api/v1/actions/:id` atualiza apenas campos operacionais permitidos.
8. `GET /api/v1/health-score` consulta o Health Score, aceitando filtro opcional por cliente.
9. `POST /api/v1/events` recebe eventos internos idempotentes, persiste payload, origem, tipo e chave externa e rejeita duplicidades sem criar uma segunda linha.
10. O middleware web não redireciona `/api/v1/*` para o login; nenhuma outra rota perde a proteção de sessão existente.
11. Os endpoints de escrita usam o cliente administrativo apenas no servidor, sem expor a `service_role` ao navegador.
12. Testes cobrem autenticação ausente, chave inválida/revogada, validações, paginação, idempotência e respostas de sucesso/erro.

## Dev Notes

- Fonte: `docs/roadmap-deep-management.md#34-api-funcional`.
- Reutilizar `api_keys.key_hash`, `revoked` e `last_used_at`; não criar um segundo mecanismo de credenciais.
- A API é para sistemas internos autorizados. Não implementar OAuth, Outlook ou Teams.
- Usar `SUPABASE_SERVICE_ROLE_KEY` somente em módulos server-only.
- Limitar paginação e tamanho de payload para evitar consultas ou eventos sem limite.
- A chave externa de evento representa a idempotência no par `(source, external_key)`.
