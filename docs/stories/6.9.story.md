## Story

Como liderança Comercial, quero visualizar quantas prospecções cada analista realizou por dia, para acompanhar o ritmo da equipe sem depender somente do total acumulado do funil.

## Contexto de Produto

- O painel Comercial já possui o total acumulado da etapa **Prospecção**, mas não registra a distribuição diária.
- O preenchimento deve continuar simples e permanecer no diálogo **Editar painel Comercial**.
- Os analistas elegíveis são derivados da configuração vigente: perfil com papel `analista` e etapa `prospecting` ativa. No cadastro atual, isso corresponde a Thiago Castro e Leticia Machado.
- Os totais acumulados existentes são preservados como legado; não haverá retroalimentação artificial de datas anteriores.

## Acceptance Criteria

1. Cada analista pode registrar uma quantidade inteira e não negativa de prospecções para uma data, com a data atual preenchida por padrão e possibilidade de informar uma data passada.
2. Datas futuras são rejeitadas e existe no máximo um registro por analista e data; salvar novamente a mesma data corrige o registro existente sem duplicá-lo.
3. O preenchimento diário fica no diálogo **Editar painel Comercial**, identificado como **Prospecções realizadas no dia**, e somente aparece para o usuário logado quando ele possui a etapa `prospecting` ativa.
4. Ao criar ou corrigir um registro diário, o total acumulado de **Prospecção** no funil é ajustado pela diferença entre o valor novo e o valor anterior, dentro da mesma transação.
5. Abaixo do bloco atual de Funil de vendas e Agenda Comercial, o dashboard exibe um gráfico de barras agrupadas com os últimos 14 dias corridos no fuso `America/Sao_Paulo`.
6. Cada data possui uma série por analista elegível, derivada de usuários com papel `analista` e etapa `prospecting` ativa; datas sem registro são exibidas com valor zero.
7. O gráfico possui título, período, legenda, tooltip, rótulos de data legíveis e estado vazio acessível quando não houver analistas elegíveis.
8. A leitura respeita a hierarquia Comercial existente; escrita e correção são permitidas somente ao próprio analista. Exclusão pelo cliente não é exposta.
9. O histórico diário começa com os registros realizados após a implantação. Totais acumulados anteriores permanecem no funil, mas não são inventados nem distribuídos retroativamente no gráfico.
10. Migração, rollback, tipos, agregador, interface e testes são atualizados; `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` e `git diff --check` passam.
